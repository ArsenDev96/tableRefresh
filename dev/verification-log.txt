-- defects found and fixed during this verification
8833132 (plugin): after a connection lost at the COMMIT, wpdb repeated the COMMIT in a new
   session, where it committed nothing; the sync reported "updated" (atomic: true) and deleted
   its journal while the table kept the old data. Reproduced on 31ad3db. Now the table is re-read;
   regression tests: lost before the COMMIT (every attempt / first attempt) and committed but
   confirmation lost. The "restore after compare-and-swap conflict" mutation survived on 31ad3db
   (undo()'s fingerprint check already prevented the restore; only the report differed); the
   conflict test now asserts that no revert is reported.
1ff4498 (test): the decompression-bomb mutation survived on libcurl 7.83 because this machine
   decompresses 1 GB in 0.9 s (< the 1.0 s limit). The test now counts decompressed bytes
   (5.9 MB with the abort, 1,073,745,920 without).
2406dcf (test env): one of 20 same-table repetitions saw "unchanged" instead of "locked": a
   process booted > 3 s late, after the winner had released the lock (it correctly wrote
   nothing). Processes now start together (TABLEREFRESH_TEST_BARRIER). New mutation: lock
   acquired without the atomic insert (caught).
65d09f6 (fixtures): /big built a 200 MB body in memory; under memory pressure that took
   25-33 s, beyond the 15 s client timeout, and blocked the fixture server. Bodies are streamed.
