which bypass WP-Cron's lock, over 25 due tables): every table is synchronized exactly once, but on
PHP 7.4 one table can end with no scheduled event ("Table N has one event. 0 is identical to 1").

   test x15, PHP 8.3 + Redis:    0 failures

stops until an administrator opens the TableRefresh list screen, which re-adds lost events
(Scheduler::reconcile). Table data is not affected. Not fixed in RC3 (sync engine unchanged by
decision); owner to decide: accept for 1.0.0 or fix in an RC4.
